# 04 — USER JOURNEY

## Entry

1. Job / interview configuration
2. Candidate context (resume when available)
3. Interview goals and competencies
4. AI disclosure
5. Device/microphone check
6. Interview begins

## Interview

### Phase A — Warm start
Short introduction. Establish conversational baseline.

### Phase B — Discovery
Ask broad questions to identify candidate experience and reasoning.

### Phase C — Adaptive deepening
Follow the highest-value uncertainty.

### Phase D — Mode transition
Move to code/debug/design/scenario only when the current evidence says it is useful.

### Phase E — Cross-panel challenge
Different role challenges a different dimension of the same evidence.

### Phase F — Verification
Clarify vague claims and reconcile contradictions.

### Phase G — Closing
Confirm no important competency remains dangerously uncertain.

## Exit

- Candidate sees completion and expected processing.
- Deep evaluation runs asynchronously.
- Final report includes scores, confidence, strengths, concerns and evidence.

## Dynamic duration

Do not use fixed “question counts” as the stopping logic.

Use:
`coverage + confidence + interview budget + hard maximum`

The interview should continue when important evidence is missing and stop when sufficient evidence has been collected.

## Candidate expectations

At the beginning clearly communicate:
- this is AI
- the approximate duration range
- voice is the primary interaction
- some tasks may involve coding/scenarios
- answers are used to adapt the interview
