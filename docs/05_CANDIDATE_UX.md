# 05 — CANDIDATE UX

## Principle

The candidate should feel like they are in one coherent interview, not operating a multi-agent dashboard.

## Main screen

Desktop:
- left/primary: active interviewer identity + voice state
- center/right: current interview content
- bottom: live transcript
- compact top bar: elapsed/remaining time, connection state, recording/disclosure indicator
- optional side rail: panel members, but only as a quiet status element

## Active interviewer

Show:
- name
- role
- listening/speaking state
- short transition context when role changes

Do not permanently show giant avatars for every persona.

## Transcript

- live but not visually noisy
- distinguish candidate vs interviewer
- timestamps available
- transcript remains useful after code/scenario mode

## Interaction controls

- microphone mute/unmute
- end interview
- repeat/clarify
- code/run/submit controls when code mode is active
- accessible keyboard shortcuts where safe

## Candidate disclosure

Before recording begins:
> “You are interacting with an AI interview panel. Your responses may be analyzed to adapt the interview and generate structured feedback.”

## Candidate mental model

“I'm talking to one interview room whose interviewer changes when there is a good reason.”

Not:
“I am chatting with several bots.”
