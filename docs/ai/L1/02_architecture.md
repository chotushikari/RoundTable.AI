# Architecture

Candidate session creation returns RTC/RTM credentials immediately. The browser enters the room while `/api/sessions/:id/start` starts the managed agent with a per-session custom-LLM credential. One agent uses Agora-managed STT/TTS and calls `/api/ai/chat/completions`; the route evaluates each substantive answer for every role, validates literal evidence, applies deterministic phase/controller rules, persists with compare-and-swap, and streams one question. Pause and repeat utterances are transcripted control turns and do not advance evidence state.

Explicit demo mode combines introduction/background in the Hiring Manager greeting, then Technical Interviewer, Product Manager, Customer, and Behavioural Interviewer each receive one short turn. Each substantive answer is evaluated for every role. Product wording adapts to missing versus claimed customer impact. Five answers trigger a closing statement; the browser finalizes after its completed transcript and idle/listening agent state. The five-minute maximum starts after agent startup; progress is server-derived from answered roles. Pause/repeat/readiness requests do not advance it. Legacy two-minute invitations retain their prior policy; normal interviews use full adaptive priorities.

Demo end-of-speech waits 1500 ms. `lib/demo-turns.ts` groups answer fragments by the server-owned pending question and reserves one accepted answer for that question. Candidate-only polling includes the pending question ID/text. The browser acknowledges `QUESTION_DELIVERED` after matching a completed agent transcript and observing idle/listening/silent state. The authenticated event endpoint checks that receipt against the current question; roles and scores remain server-owned. An undelivered question is repeated; partial sentences stay pending. Durable private session events hold receipts, fragment text, and cached responses under the existing retention policy. Local memory turn reservation is synchronous to match the database's atomic uniqueness guarantee.

Supabase is the production store and auth provider. An in-memory adapter is development/test-only and is prohibited in production. E2B is called only by the server-selected workspace harness. Changes from `company_session_status` are broadcast to a private organization topic; no content table is added to the Realtime publication.
