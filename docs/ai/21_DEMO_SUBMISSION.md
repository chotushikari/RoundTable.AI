# 21 — DEMO & SUBMISSION

## Demo story

One continuous interview.

1. AI disclosure
2. Technical question
3. Candidate gives strong implementation reasoning
4. Candidate State visibly updates
5. Product impact remains uncertain
6. Product takes over
7. Candidate gives vague outcome
8. System asks for a measurable metric
9. Candidate interrupts agent
10. Optional code task opens
11. Test results become evidence
12. Final assessment cites evidence

## What judges must notice

The next question should be impossible to justify without the previous evidence.

## Submission artifacts

- working prototype
- GitHub repository
- project description
- demo video
- technical architecture
- Agora integration details
- pitch deck
- setup instructions
- requirement coverage matrix

## Demo failure plan

Prepare:
- a deterministic test scenario
- a reset path
- a safe fallback interviewer response
- a short recording as backup evidence
- a second browser/device path if available

Do not fake the mandatory Agora functionality in the primary demo.

## Final checklist

- AI disclosure works
- voice works
- interruption works
- multi-role works
- state persists
- dynamic follow-up works
- role-play works
- difficulty changes continuously
- vague detection works
- contradiction handling works
- evidence links work
- assessment works
- no critical console/server errors
